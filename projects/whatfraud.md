# 02 · 사기방지위원회

**AI 캐릭터와 실시간으로 대화하며 스마트폰 금융사기를 체험하는 웹 게임입니다. 내가 어떻게 반응하고 대처했는지, 선택에 맞춘 보고서로 돌아봅니다.**

> **참여 역할** · 기획 · 기능·스토리 구성 · Suno 음악 작업  
> 2인 공동 개발

## AI와 대화하며 사기 상황에 대응하기

1. 지인 사칭 → 투자 권유 → 피해 회복 사칭으로 이어지는 세 상황을 만납니다.
2. 주요 대화 장면에서 직접 질문하거나 게임 속 기록을 보냅니다. AI 캐릭터가 현재 상황과 자료에 맞춰 답합니다.
3. 연락처·돈을 받을 사람·안내 자료를 비교하고, 확인·보류·차단·가상 송금 등을 선택합니다.

실제 범죄에 대비해 내가 어떻게 반응하고 대처하는지 살펴보도록 만들었습니다.

[게임 실행](https://whatfraud.hoyhoy1227.chatgpt.site/) · [게임 소개와 플레이 안내](https://github.com/hoyhoy1227/whatfraud)

## 내 선택에 맞춘 대응 보고서

무엇을 먼저 확인했는지, 송금했는지, 증거를 남겼는지를 바탕으로 잘한 대응과 주의할 점을 짚어 줍니다. ‘확인하겠다’고 답한 뒤 실제로는 송금했다면, 말과 행동이 달랐던 지점도 보여 줍니다.

선택 직전으로 되감아 다른 대응을 해 보고, 원래 결과와 비교할 수 있습니다.

보고서는 플레이 기록과 정해진 분석 규칙으로 구성합니다. [보고서 코드](https://github.com/hoyhoy1227/whatfraud/blob/main/app/story/response-report.js) · [보고서 화면](https://github.com/hoyhoy1227/whatfraud/blob/main/app/story/analysis-report.tsx)

## 플레이 중 발견한 대화 오류

- **실제 친구가 다시 본인 확인을 권함** · 준호 본인과 대화 중인데 다른 연락처로 확인하라고 답했습니다. 캐릭터가 아는 사실과 플레이어가 이미 한 행동을 답변에 반영했습니다.
- **자료를 보내자 답변이 멈춤** · 화면에서 고른 첨부를 서버가 거절했습니다. 화면과 서버가 같은 첨부 목록을 쓰도록 맞췄습니다.
- **정상적인 대사도 검사에 막힘** · 문장 수와 물음표 제한이 원인이었습니다. 표현 검사와 게임 진행 검사를 나누고, 실패할 때 쓸 대사도 고쳤습니다.

AI는 캐릭터의 답변을 만들고, 게임 엔진은 사건·잔액·결말을 관리합니다. [실제 오류와 수정 과정](development-cases.md)

## 게임 경험과 사용 기술

가상의 스마트폰에서 연락처·은행·브라우저·메모를 오가며 연락과 기록을 비교하고, 답장·보류·차단·가상 송금으로 대응합니다. 지인 사칭 → 투자 자료방 → 회복 지원 사칭 시나리오를 거친 뒤 하루 끝 보고서와 되감기로 다른 선택을 돌아봅니다. 실제 송금·전화·신고를 수행하는 서비스는 아닙니다.

**사용 기술:** React · TypeScript · Next.js 호환 앱 구조 · Vinext/Vite · 서버 Gemini API · Git/GitHub

## 대화를 게임에 넣을 때 생긴 문제

정해진 대사만 반복하는 게임은 상황에 맞는 반응을 주기 어렵습니다. 반대로 LLM에 대화를 완전히 맡기면 이전 선택, 금액, 거래·증거와 충돌하거나 사건의 사실을 임의로 바꿀 수 있습니다.

**목표:** 캐릭터는 상황에 맞게 답하되, AI가 사건의 사실이나 게임 규칙을 바꾸지 않게 하는 것.

## 대화가 화면에 나오기까지

```mermaid
flowchart LR
    A["사용자 발화·게임 맥락"] --> B["장면/인물/첨부 조건 검증"]
    B --> C["역할별 프롬프트 구성"]
    C --> D["Gemini API"]
    D --> E{"생성 결과 검증"}
    E -->|통과| F["캐릭터 응답 표시"]
    E -->|실패/지연| G["내장 대사로 전환"]
    A --> H["독립적인 진행/이벤트 엔진"]
    H --> I["선택·거래·증거·결말 결정"]
```

- 서버의 `/api/ai-chat`에서 입력·문맥을 검증하고 외부 Gemini API를 호출합니다.
- AI는 **제한된 장면의 캐릭터 발화**를 생성합니다. 가상 송금, 사건 순서, 잔액, 결말은 별도의 결정적 이벤트 엔진이 관리합니다.
- 게임 내 AI 사용 기회는 사건별 **2/2/1회, 새 회차 전체 최대 5회**입니다. 실패·취소 시도도 사용량에 남을 수 있습니다. 이는 외부 Gemini HTTP 요청이 총 5회 이하라는 뜻이 아닙니다.
- 서버는 응답 형식·표현 품질이 기준을 통과하지 못하면 **요청당 최대 1회 교정 생성**을 시도합니다. 원래 제한 시간과 호출 제한을 유지하고, 교정에도 공유 예산을 다시 예약합니다. 전송 오류·할당량 실패에 대한 무제한 재시도는 하지 않습니다.
- 지연, 호출 실패, 부적절한 생성 결과는 검사 후 준비된 메시지로 대체할 수 있어 AI 없이도 완주할 수 있습니다.

## 제작 중 실제로 마주친 답변 오류

개발 당시 실응답 검수와 사용자 재현 보고를 중심으로 정리했습니다. 이번에 새로 생성한 응답이나 모의 응답을 실제 사례로 바꿔 적은 것이 아닙니다.

| 실제 상황·관찰 | 원인과 수정 |
| --- | --- |
| 추가 송금을 이미 멈췄다고 전했는데 “응, 지금 송금하지 말고 화면이랑 기록부터 같이 보자.”라고 답함 | 완료한 행동과 다음 확인을 구분하지 못함. 플레이어가 완료한 행동·현재 단계·전달한 첨부를 문맥에 반영 |
| 실제 준호에게 사칭 연락을 알렸는데 저장된 연락처로 다시 확인하라는 취지로 답함 | 일반적인 안전 안내와 인물의 지식 충돌. 준호 본인이 아는 사칭 여부부터 답하고 첨부에 반응하도록 보완 |
| 지수에게 ‘수익 인증 글’을 첨부하면 답변 실패 | 화면과 서버의 첨부 허용 목록 불일치. 공유 목록·응답 focus·준비 대사를 함께 맞춤 |
| 준호의 보완 대사도 서버 검사에서 차단됨 | ‘한별 서비스?’가 당시 최대 두 문장·물음표 제한과 충돌. 보완 대사를 수정하고 자연어 표현 검사와 안전·분기 검사를 분리 |
| AI 답장을 받은 뒤 송금·후속 메시지를 보내면 순서가 뒤바뀜 | 고정 슬롯 대신 발생 순서의 transcript를 사용하고 본편 답장은 발생 단계에 유지 |

**배운 점:** 말투뿐 아니라 캐릭터가 아는 사실, 첨부 목록, 메시지 순서도 맞아야 대화가 자연스럽습니다. 답변이 없을 때는 모델 호출·첨부 처리·답변 검사를 나눠 원인을 찾았습니다.

[상황 → 관찰 → 원인 → 수정 과정의 전체 사례](development-cases.md) · [원본 개발 기록](https://github.com/hoyhoy1227/whatfraud/blob/a4289958c7c66724df7d25b6475aacc7328b1c46/docs/development/DEVELOPMENT_JOURNEY.md)

코드에 수정이 반영된 사실과 수정 뒤 실제 응답이 좋아진 사실은 구분했습니다. 일부 마지막 보완은 실응답 재검수가 없어 해결 완료·성공률로 표시하지 않았습니다. [자동·모의 검사는 보조 근거로 분리](../verification/2026-11-01/README.md)했습니다.

## 만들며 배운 점

자연스럽게 답하는 것만으로는 충분하지 않았습니다. **AI가 만드는 대사와 코드가 결정하는 사건을 나누고**, 캐릭터가 아는 사실까지 맞춰야 플레이가 이어졌습니다.
