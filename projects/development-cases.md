# 제작 중 마주친 실제 오류와 대응

게임은 개발 당시의 실제 답변과 오류 보고를, 수어는 실행 기록과 저장된 예측을 바탕으로 정리했습니다. 새로 호출해 만든 결과는 아닙니다. 자동 검사 결과는 [보조 검증 기록](../verification/2026-11-01/README.md)에 정리했습니다.

## 사기방지위원회 · 맥락과 다른 답변

### 이미 멈춘 행동을 다시 지시

- **상황:** 개발 초기, 준호에게 송금한 뒤 추가 송금은 멈췄으며 함께 확인하고 싶다는 뜻을 전했습니다.
- **당시 실제 답장:** “응, 지금 송금하지 말고 화면이랑 기록부터 같이 보자.”
- **문제:** 함께 확인하자는 방향은 맞지만, 이미 중단했다는 플레이어의 말을 반영하지 못했습니다.
- **대응:** 현재까지 완료한 행동·사건 단계·실제로 전달한 첨부를 문맥에 넣고, 이미 끝난 행동을 다시 지시하지 않도록 프롬프트를 보완했습니다. 화면에 있는 문맥과 서버에 전달하는 상태도 맞췄습니다.
- **확인 범위:** 위 답장은 당시 실호출 검수에 남은 사례입니다. 아래 대응의 현재 구현은 확인했지만 이 사례의 수정 전후 실응답을 같은 조건으로 새로 비교하지 않았습니다.

### 실제 친구가 다른 연락처로 다시 확인하라고 답함

- **상황:** 사칭 계정의 연락을 실제 준호에게 알렸습니다.
- **관찰한 답변:** “저장된 연락처로 확인하자”는 취지로 답했습니다.
- **문제:** 준호 본인과 대화 중인데 다른 연락처로 확인하라고 답해 앞뒤가 맞지 않았습니다.
- **대응:** 준호가 아는 사실인 ‘새 계정은 내 계정이 아니며 결제를 부탁하지 않았다’를 먼저 답하도록 인물 문맥을 명시했습니다. 이 사실을 빠뜨린 답변에는 인물·첨부별 보완 대사를 사용했습니다.
- **설계 판단:** 대화가 자연스러우려면 **누가 무엇을 알고 있는지**부터 맞아야 했습니다.

## 사기방지위원회 · 답변이 나오지 않은 경우

### 화면에서 선택한 첨부가 서버에서 거절됨

- **재현:** 지수와의 대화에서 화면에 있는 ‘수익 인증 글’을 첨부해 전송했습니다.
- **증상:** 첨부는 선택됐지만 정상 답변으로 이어지지 않았습니다.
- **확인한 원인:** 화면과 서버의 첨부 허용 목록이 달랐습니다. 화면이 허용한 선택을 서버가 거절했습니다.
- **수정:** `storyAttachments`를 화면·서버에서 공유하고, 허용 첨부·응답의 `focus`·준비 대사를 함께 맞췄습니다. [관련 커밋](https://github.com/hoyhoy1227/whatfraud/commit/1ed87d4)
- **확인 범위:** 제작 대화의 오류 보고와 수정 기록, 현재 공유 목록 구현을 대조했습니다. 수정 뒤 모든 첨부의 실제 Gemini 응답이 안정됐다는 뜻은 아닙니다.

### 정상적인 보완 대사가 응답 검사에 걸림

- **상황:** 준호의 수취인·프로필 반응을 보완한 뒤 실제 응답을 재검사했습니다.
- **증상:** 생성 답변을 보완하는 준비 대사마저 서버가 차단했습니다.
- **확인한 원인:** “한별 서비스?”가 포함된 대사가 당시 기준에서 세 문장으로 계산되어 **최대 두 문장** 제한과 충돌했고, 물음표 제한에도 걸렸습니다.
- **수정 과정:** 우선 물음표 없는 두 문장으로 보완 대사를 수정했습니다. 이후 자연어 표현의 과도한 검사를 완화하면서 JSON 구조·상태 조합·위험 표현 검사는 유지했습니다. 현재의 문장 제한을 과거 두 문장 제한과 혼동하지 않습니다.
- **확인 범위:** 오류가 난 재검수 기록과 코드 수정을 연결했습니다. 마지막 보완 직후의 실응답 재검수는 별도 기록이 없어 완료로 표시하지 않습니다.

답변이 멈춘 원인은 첨부 목록, 문장 검사, 진행 상황, 요청 대기 등으로 달랐습니다. 검사에 걸린 답변은 원래 메시지와 자료를 유지한 채 다시 생성하고, 계속 실패하면 준비된 대사로 이어지게 했습니다. 송금·신고·환급이 끝났다고 사실과 다르게 말하는 답변은 통과시키지 않았습니다.

### 답장은 있었지만 순서가 뒤바뀜

2막에서 **AI 답장 → 가상 송금 → 후속 메시지** 순으로 진행했는데, 새 메시지가 이전 AI 답장 앞에 끼고 AI 답장은 계속 맨 아래에 남는 재현 보고가 있었습니다. `sent / preparedSent / reply`에 따로 저장하던 메시지를 보낸 순서대로 `transcript`에 담았습니다. AI 답장도 실제 발생한 단계에 두어, 화면을 움직여도 대화 순서가 바뀌지 않게 고쳤습니다.

## 한국수어 Gloss · 입력과 출력의 차이

이 사례는 초기 KE-T5와 v4의 개발 기록입니다. [v8 실험과 평가 결과](ksl-gloss.md)

입력은 실제 오류를 설명할 수 있는 비슷한 문장으로 바꿨습니다. 출력은 당시 기록의 일부입니다.

| 입력 예시 → 관찰된 출력 조각 | 문제점 |
| --- | --- |
| “주말에 전시를 보러 갈래요.” → `지시1` | 문장 내용과 무관한 한 단어만 출력 (초기 KE-T5) |
| “동료가 없어 혼자 점심을 먹었어요.” → `할아버지1` | 문장에 없는 인물이 등장 (초기 KE-T5) |
| “손짓의 뜻을 설명해 줄래요?” → `제스처 제스처` | 표기 번호 누락과 같은 단어 반복 (이전 pko-T5 v4) |

입력의 뜻을 담았는지와 Gloss 표기가 맞는지를 따로 살폈습니다. 초기 KE-T5와 pko-T5 v4는 서로 다른 실험 단계입니다.

### 입력을 넣었지만 추론이 시작되지 않은 경우

초기 어댑터를 불러올 때 `lm_head`의 체크포인트 크기 `[64128, 512]`와 당시 기반 모델 크기 `[64100, 512]`가 달라 `size mismatch`로 중단된 터미널 기록이 있습니다. 학습 당시 토크나이저·확장 어휘 크기로 embedding을 맞춘 뒤 어댑터를 읽도록 로딩 순서를 고쳤습니다. 번역 결과가 틀린 문제가 아니라, 모델을 불러오는 단계에서 생긴 오류였습니다.

### v4 저장 예측에서 확인한 오류

제공된 최종 패키지의 `pko_t5_base_ksl_nikl_2024_adapter_v4/repeat_safe_general_700` 저장 예측을 로컬에서 확인했습니다. 번호형 경로에서 **`한글지문자 문자지문자`**, **`제스처 제스처`** 같은 생성이 남아 있었습니다. 공개 집계의 표기 체계 불일치와 일치하는 관찰이며, 이번에 모델을 새로 실행한 결과는 아닙니다.

당시 v4 구성은 `paust/pko-t5-base` + LoRA / `lm_head`, 표기 체계별 어댑터, 기본 no-RAG입니다. 데이터 정규화·중복 제거·문장 그룹 분할과 학습 구성을 함께 바꿨으므로 특정 한 변경이 오류를 모두 해결했다고 단정하지 않습니다. WER·평가 표본·다중 정답 조건은 [수어 상세 사례](ksl-gloss.md)에 따로 남겼습니다.
